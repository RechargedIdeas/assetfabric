## [0.7.11+f7] — 2026-11-20 — Quality gaps Q3: swap advisor < 50 ms on 2 cores (GAME_SPEC §4.1)

### Changed
- **Swap advisor meets the < 50 ms target** (quality gap P3, was ≈ 50–100 ms): `tools/swapbench.gd` (`--scene=swapbench`)
  samples 17 real freeze states (party_ai pack fight + Cave Warden, every 60 ticks while ≥ 2 fighters live) and times
  `SwapAdvisor.rank` 5× each. `forge accept F3` runs it **pinned to 2 CPU cores** (`taskset`, weakest node) and gates
  p95 ≤ 50 ms, max ≤ 150 ms, threaded == serial ranking, and LOD fidelity (shipped 15 Hz-LOD top pick inside the
  full-fidelity LOD-1 top 2 in every state, top-1 agreement ≥ 80 %). Recorded on the 8-vCPU box pinned to CPUs 0,1:
  **p50 23.4 ms, p95 37.0 ms, max 48.6 ms**; LOD fidelity 17/17 top-1 agreement. In-game freezes: party scene 28 ms;
  F4 live-tune freeze 73.6 → 32.7 ms.
- Pure GDScript, no GDExtension: hot-path data-layout work in the forward sims — a struct-of-arrays mirror of the fields
  entities read off each other inside `step()` (packed-array reads instead of script-property reads, which serialised
  worker threads: 2 threads ran 2.2× slower than 1), BT memory as plain members instead of `set_meta`/`get_meta`
  (global StringName table), ready abilities computed once per think, the 7-feature policy dot product unrolled in the
  same operation order (bit-identical scores), per-clone private Strings/containers (`isolate()`), BFS field tables
  cached per layout, no per-tick `outcome()` scan in the forward horizon.
- **Behaviour unchanged**: F2–F6 re-recorded — fight outcomes, ticks, state hashes, G-BAL-01 matrices, per-pair spreads
  and slice results identical to 0.7.10; only timings moved. Side effect: F5 Monte Carlo 280 → 161 ms per encounter per
  worker, F6 slice wall 4.6 → 2.7 s.

### Added
- `forge/cpus.py`: "2 cores" = two **physical** cores — the swapbench and GroundWeave's 2-core pinning take one logical
  CPU per core (`thread_siblings_list`); on SMT CI runners `0,1` are one core's two threads (that measured p95 66 ms).
- GroundWeave `runtime.girt` probe (C8) runs the swapbench too, so the F3 gate holds on the 2-core GPU-hidden node.
- `tests/test_f3_ai.py`: swapbench gate unit tests (target, ceiling, pinning, sample count, parity, fidelity).

## [0.7.10+f7] — 2026-11-20 — Quality gaps Q2: G-A11Y-01 full (Settings screen, rebinding, live colour-blind palette)

### Added
- **In-game Settings screen** (`games/game-zero/ui/settings_menu.gd`): opened with the `settings` action (Escape / F10 /
  pad Start) from character select or during play (the world pauses). Rebind any action to a key, pad button or stick
  direction (accept a row, press the new input; Escape cancels); a binding another simultaneously-read action already
  uses is swapped (`Fabric.rebind`, contexts `play` / `freeze`). Palette row ◀ ▶ switches Default / Deuteranopia /
  Protanopia live. Keyboard and gamepad navigable (Godot `ui_*` + explicit pad A/B, d-pad, left stick); all text locale
  keys (54 new). Every change is saved immediately.
- **Full input map**: every input the game reads is an InputMap action with keyboard + gamepad defaults — new
  `use_salve` (H / pad B), `command` (/), `settings`, `swap_pick_1…4` (1–4 / d-pad during freeze); no `is_key_pressed`
  or `KEY_*` left in scenes (test-enforced). Binding tokens: key name, `pad:<button>`, `axis:<axis>:±`; old keyboard-only
  remaps load unchanged. On-screen hints are templates (`{interact}` …) filled with the current bindings.
- **Live colour-blind palette** (`autoload/a11y.gd` + `ui/palette_remap.gdshader`): a full-screen post-process remaps
  every PatternVault colour a variant changes (sprites, tiles, crop plots, HUD) without reloading; hidden (zero cost) on
  Default. The table is generated by Codegen-World from `content/patternvault/palettes.json` into `world.json` `a11y`
  (`forge/a11y.py`); crop plots now use PatternVault `ui_roles` colours plus a shape cue (ready = framed).
- **Palette gate** `a11y_palettes` (Codegen-World): Machado 2009 CVD simulation + CIE76 ΔE — each variant must separate
  5 signal pairs (crop growing/ready, red/green UI, hostile/hero, hostile on two moss floors) by ≥ 25 ΔE under its
  deficiency and never worse than Default; the table must be unique with no collateral recolouring. Default palette under
  deuteranopia: red/green UI 14.1 ΔE, hostile on moss 19.2 → variant 110.4 / 78.1; protanopia hostile on dark moss 7.5 → 64.3.
  New variants for `ui_retro` (green → blue) and `hero_amber` (its accent shares the hostile red).
- **`--scene=a11ycheck`** acceptance driver: plays the Settings screen with injected keyboard + gamepad events, then a
  fresh process verifies the restore; with a display writes per-palette captures that forge checks pixel-exactly.

### Changed
- **G-A11Y-01 is a full pass** in `forge accept F7` (was partial, INFERENCE F7-11): fast mode (pytest/CI) gates the
  Settings-screen run, the restore, the palette gate and — where `xvfb-run` exists (CI installs it) — the render check;
  full mode also round-trips keyboard + gamepad bindings + palette through desktop / Android content / Web saves.
- Settings persistence: checkpoint saves carry the player's current settings (before, `to_save` wrote defaults and would
  have wiped a remap); settings changed before the first save go to `settings.json` beside the slot.
- `--ci-group=game` now also installs the cached Xvfb/ffmpeg packages (render check).
- Encounter overlay: tactic + focus words are locale keys (were literal English).

## [0.7.9+f7] — 2026-11-20 — Quality gaps Q1: CI shards, gap inventory, stale descriptions

### Changed
- **CI wall time** (quality gap P1): the single ≈ 13 min pytest job is now a 3-way matrix `pytest --ci-group=game|recon|core`
  (`tests/conftest.py`). The groups partition the suite — every test is in exactly one shard, anything unlisted is `core` —
  so coverage is unchanged; `tests/test_ci_groups.py` guards the partition and fails on stale shard references. uv download
  cache and an apt package cache (ffmpeg/Xvfb/Qt libs, skipped on the `game` shard) replace the per-run `apt-get`;
  superseded runs on `feat/**` are cancelled (`main` never). Full-mode companion accepts stay in the parallel `pocketloom` job.
- `forge/milestones.py` C10–C12 descriptions (and so STATUS.md) no longer call ARCore / video / dense depth /
  photogrammetry / MeshWeaver / GDGS "labelled stubs" — they became real in 0.7.5–0.7.7; STATUS regenerated (was `0.7.7+f7`).
- TODO.md: prioritised quality-gap inventory (P1–P10) with gates and batches; hardware/Producer-gated items listed separately.

## [0.7.8+f7] — 2026-11-20 — Stub replacement batch 4: VoiceBridge (Vosk), persona micro-LM (Qwen2.5-0.5B), Studio surfaces

### Added
- **VoiceBridge** (`forge/voice.py`, ADR-0006): offline Vosk STT (`vosk` 0.3.45, Apache-2.0) with **vosk-model-small-en-us-0.15**
  (Apache-2.0, 41 MB zip, pinned URL + SHA-256, unpacked into gitignored `store/models/`). The recogniser is constrained to the
  closed intent grammar (70 phrases built from `intent_grammar.gd` `VERBS` + the roster; out-of-lexicon `emberling` is spoken
  as `em berling` and mapped back); a word-confidence gate (< 0.7 → `unknown`, reason `low_confidence`) prefers a re-ask to
  a wrong action. `parse` mirrors `IntentGrammar.parse` and reads `VERBS` from the GDScript file, so typed and spoken commands
  share one grammar. CLI `forge voice grammar|transcribe|intent|eval`. GroundWeave op `stt.voice` (`vosk-small-grammar-cpu`,
  `requires_model`). Synthetic speech (espeak-ng, 10 commands × 2 voices, committed fixtures `tests/fixtures/voice/`):
  **accuracy 0.90, wrong-action rate 0.05** (the only confident error: “hold” heard as “go” — C-79); 4 voices × 2 speeds
  fresh renders: 0.89 / 0.05. Unconstrained decoding of the same audio: 0.18 — the grammar is what makes it usable.
- **Persona micro-LM** (`forge/microlm.py`): the spec's shared backbone **Qwen2.5-0.5B-Instruct** (Apache-2.0), int8 ONNX
  (onnx-community, pinned revision, SHA-256, 512 MB) on the onnxruntime CPU EP with an own KV-cache decoding loop (greedy or
  seeded top-k) and `tokenizers` (Apache-2.0). Persona cards (traits + the persona's own lines as few-shot turns); every draft
  passes the callout content-safety gateway plus a meta-chatter filter. `forge persona author --persona P --event E [-n] [--write]`
  appends accepted drafts to `content/personas/lm_drafts.yaml` as `reviewed: false`; only `reviewed: true` lines are merged into
  the callout cache. The game never loads the LM (G-AI-03); in-engine runtime stays the cache + bigram. ≈ 6 tok/s on 1 thread,
  1–3 s per line on 2. GroundWeave op `lm.persona` (`qwen2.5-0.5b-int8-onnx-cpu`; `qwen-lora-rocm` planned — C-80).
- **Studio** (`studio/assetfabric_studio/app.py`): new tabs **Swatches** (SwatchStudio — every PatternVault palette and
  colour-blind variant as swatches), **Voice** (WAV → transcript → intent) and **Persona** (micro-LM drafts for review; Studio
  writes nothing); the Console runs `/help /status /models /palettes /intent <text>` from a closed read-only allow-list
  (remote phone input lands in the same box — C-81). Offscreen-tested.
- `forge models` registry: `unpack: zip` entries (verified archive → idempotent safe extraction).
- Tests `tests/test_b4_voice_lm.py` (model-backed ones skip without the weights; CI does not fetch them).

### Changed
- Extras: new `voice` (vosk) and `lm` (onnxruntime, tokenizers); both added to `dev`.
- `callouts` generator merges human-reviewed micro-LM drafts (none today → cache bytes unchanged).
- Version `0.7.7+f7` → `0.7.8+f7` (PocketLoom app unchanged, `0.4.0-c11`). INFERENCES C-78…C-83.

## [0.7.7+f7] — 2026-11-20 — Stub replacement batch 3: C12 CPU photogrammetry, SplatForge CPU rung, MeshWeaver, GDGS Godot import

### Added
- **CPU photogrammetry** (`forge/photogrammetry.py`, `realityloom.Photogrammetry`): OpenCV SIFT features, ratio test +
  fundamental-matrix RANSAC, union-find tracks (inconsistent tracks dropped), initial pair from a USAC_ACCURATE essential
  matrix scored by inliers × baseline angle, incremental SQPnP registration + LM refine, multi-view DLT triangulation, three
  alternating refine passes; single-threaded and seeded (deterministic). Writes `<bundle>/sfm/sparse.ply` + `cameras.json`.
  CLI `forge recon photogrammetry BUNDLE [--focal-px]`. GroundWeave op `recon.sfm` (`opencv-sift-sfm-cpu`).
  Rendered textured scene, 12 views on 120°: all registered, rotation error 0.38°, centre error 1.1 %, reprojection RMSE 1.26 px
  (floors 2° / 5 % / 2 px). No bundle adjustment, no dense MVS (C-74).
- **MeshWeaver** (`forge/splats.py`, `realityloom.MeshWeaver`): INRIA `.ply` splats → Gaussian density grid → surface nets
  (own NumPy) → OBJ. CLI `forge recon mesh PLY [--out] [--voxel]`; op `recon.mesh` (`meshweaver-density-surfacenets-cpu`).
  Sphere of splats: median vertex radius 0.5007 (r = 0.5).
- **GDGS import** (`realityloom.GdgsImport`): INRIA `.ply` → Godot `.tscn` with a MultiMesh of camera-facing billboard quads
  (colour from SH DC, alpha from opacity, size from scale), Compatibility renderer. CLI `forge recon godot-import PLY --project
  DIR [--verify]`; op `shuttle.gdgs` (`gdgs-multimesh-billboard-cpu`). Verified in Godot 4.3 under Xvfb (opengl3): instance
  read-back + a 320×240 render with 5637 lit pixels.
- **SplatForge CPU rung** (`forge/splattrain.py`, `realityloom.SplatForgeCPU`): own NumPy 3D Gaussian Splatting trainer —
  isotropic Gaussians, SH degree 0, dense depth-sorted front-to-back alpha compositing (α ≤ 0.99), analytic backward pass
  (checked against finite differences to ~1e-8 relative), Adam, opacity pruning; BLAS-free matmuls so the trained `.ply` is
  byte-identical at any thread count. Bundle → CPU SfM poses + sparse init → training → `<bundle>/splat/point_cloud.ply`
  (validated) + `train.json`. CLI `forge recon train BUNDLE --stage splat-cpu [--splats --width --iters --focal-px
  --holdout]`; bounded to ≤ 2000 splats, ≤ 96 px, ≤ 24 views (refuses beyond). GroundWeave op `recon.splat_cpu`
  (`splatforge-numpy-cpu`). Rendered 9-view scene, SfM poses, middle view held out: held-out PSNR 23.3 dB vs 10.2 dB untrained
  (+13.1 dB), 600 splats × 400 steps at 64×48 in ≈ 60 s on one core (floors 20 dB / +10 dB). C-77.
- Accept C12: `photogrammetry`, `splat_cpu`, `meshweaver`, `gdgs`; tests `tests/test_c12_real.py`.

- **LoomCluster (C7)** `forge/loomcluster.py`, `forge cluster node|submit|status|gen|demo`: equal nodes (one program, no master) that **advertise** cores/devices/allocation-capped slots and gossip a mesh; any node accepts jobs; **work stealing** from the busiest peer's queue tail; **leases** at the job's origin (owner moves with a steal) so a crashed node's work re-runs elsewhere; failing jobs **retry** (`max_attempts`, default 3) then report; an append-only **journal** lets a restarted node recover held jobs and results, and peers park + **redeliver** results for an origin that is down; **device negotiation** places `requires.device` jobs on a node advertising it and refuses when none does; the elected coordinator (lowest live id) is reporting-only. `gen` jobs run in child processes (true parallelism; the child sees only the devices the node advertises). `forge cluster gen --out` lands artifact bytes identical to a local build.
- **PocketLoom ↔ cluster**: `forge link serve --cluster <node URL>` — a paired phone's `hashchain`/`gen` offloads are round-robined over the fleet (`via: "loomcluster"`), falling back to the desktop if the fleet is unreachable.
- **GroundWeave (C8)** `forge/groundweave.py`, `content/groundweave/ladder.yaml`, `forge groundweave check|show|verify`: per-op GPU→CPU ladder (rocm / directml / vulkan → cpu); rules enforced by `check` (real CPU rung last or `gpu_required` + `route: loomcluster`; every generator kind declared); `select` never picks a `planned` rung; `execute` demotes a failing GPU rung at runtime; **`forge build`/`run_brief` refuses a generator with no ladder entry**; `verify` runs every op's CPU path pinned to 2 cores with GPUs hidden against its budget and demands output **byte-identical** to the unpinned run and to a run with every GPU simulated present; Godot-headless probes for GIRT (F3 run, policy p95 ≤ in-engine budget) and a reduced balance matrix. `forge status` reports the ladder.
- `forge accept C7`, `C8`, `C7-C8` with `docs/acceptance-tests/results/C7.json|C8.json`; `docs/acceptance-tests/C7-C8.md`; `tests/test_c7_c8.py` (14 tests, ≈ 7 s); CI: `forge accept C7-C8` runs in the existing parallel `pocketloom` job (Godot cached) — the `test` job (critical path) only gains the 7 s of unit tests.
- `forge.yaml` `cluster.protocol` (+ schema) and the full fleet (main, secondary, redmi, lemur, nokia, kindle-1/2).

### Changed
- Taken from `wip/f5-companions` and fixed: the draft's steal path told the origin about the new owner only *after* the thief ran, so a node killed right after a steal stranded the job — ownership now moves with the job; ops moved out of threads into child processes; results from an unreachable origin were dropped — now parked + redelivered; `loomlink.py` (already on main) is the single source of the `hashchain`/`gen` ops. `gen` ops now go through GroundWeave and can return artifact bytes (`return_data`).
