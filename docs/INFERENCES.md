## F1 — Content Pipeline

17. **Procedural G1-Sprite backend** (template humanoid/beast, 6-frame sheet idle/walk/attack) stands in for the 2–4 MB ONNX Tiny model; same generator interface so the ONNX backend can replace it.
18. **Cellular-automata G1-Tile backend** stands in for the ~2 MB NCA model; CMA-ME diversity search deferred. Solvability gate is BFS (A* equivalent on a uniform grid).
19. **DyeWorks procedural = periodic value noise** quantised to a PatternVault ramp + derived normal map; diffusion backends optional later.
20. **Pure-Python PNG codec** (`forge/imaging.py`) instead of Pillow — keeps generators dependency-free on the 2-core/no-GPU node.
21. **Runtime asset loading** (`Image.load_from_file` + `.gdignore`) instead of Godot editor import presets: Godot 4.3 has no headless `--import`, and runtime loading is what F4 hot reload needs. Pixel presets = project-wide nearest filter + per-node `texture_filter`.
22. **`fabric_assets.json` registry** as the Godot binding contract (G-FAB-01 zero manual wiring).
23. **Determinism gate**: committed generated assets must equal regenerated bytes (SHA-256).
24. **SwatchStudio F1 scope** = `forge palette` terminal swatches + colour-blind variants; the live PySide6 tuning panel arrives with the Studio shell.
25. **Sandbox encounter stats** (`data/encounters/sandbox.json`) hand-authored for F1; F2 codegen replaces them.
26. **Autoplay agent + `FABRIC_RESULT` line** as the headless acceptance protocol; recorded in `docs/acceptance-tests/results/`.
27. **Hero/enemy names** (Kael, Emberling) are placeholders pending GAME_SPEC §10 decisions.

29. **Ability model**: types melee / ranged (hitscan) / aoe / heal / taunt; damage = max(1, round(atk × power − def)); priority = list order.

31. **Tier scaling**: multiplier 1.0 / 1.6 / 3.2 on hp/atk/def.

## F3 — GIRT + CascadeHub + micro-LM path + callouts

37. **GIRT backend for F3 = pure GDScript** (`mlp-gdscript`, `persona-bigram`): no ONNX Runtime GDExtension yet. Model files are JSON so they stay ONNX-exportable; the facade (registry, budgets, telemetry, refusal in tick) is the contract ADR-0004 asks for.
38. **P-TargetSelect** features (dist, hp ratio, hp, tier, atk, in-range, threatens-low-ally), K = 4 candidates, MLP 7→12→1 tanh, trained by behaviour cloning on a focus-fire teacher utility (NumPy, seed 4). Teacher weights are ours.
39. **Persona "micro-LM" = per-persona bigram table + LCG sampler with a repetition guard** — a deterministic stand-in for the spec's LoRA micro-LMs until a real small LM backend exists. Exact Python ↔ GDScript parity is a gate.
40. **Callout cache** = persona templates × ally/foe word slots, expanded offline and safety-gated (length, blocklist, unresolved slots); `%ALLY%` resolved at runtime. Personas and lines in `content/personas/personas.yaml` are ours.
41. **Behaviour-tree vocabulary** (selector/sequence/condition/action; leaves is_casting, ally_needs_heal, should_taunt, tactic_defensive, not_threatened, cast_heal, cast_taunt, select_target, engage, regroup, idle) and tree shapes.
42. **Retarget at 10 Hz** (every 6 ticks, or when target dies / focus intent changes) instead of every tick.
43. **Swap advisor scoring**: Δfoe HP − 1.5·Δparty HP + 2·(candidate damage+healing) + 20·candidate HP ratio + 50 if victory; horizon 120 ticks (spec "~2 s"), forward-sim brains at 15 Hz (LOD 4), movement at 60 Hz.
44. **Swap budget**: GAME_SPEC's "< 50 ms" is tracked as a soft target; hard gate is 150 ms. Parallel candidates on WorkerThreadPool with per-thread forks (brain, grid, abilities) — identical results to serial (tested).
45. **Intent grammar** verbs (focus/target/attack/hit, regroup/fall back/retreat, defend/hold, charge/push/go, swap/switch) — closed vocabulary shared with the future Vosk path (ADR-0006).
46. **CascadeHub** topics (`intent`, `callout_request`, `callout`, `dialogue_request`) drained once after each fixed tick, never inside it.
47. **Demo/attract mode**: windowed `--autoplay` plays the encounter script and holds the freeze overlay 90 frames so it can be captured.

## F4 — Substrate: sandbox, hot reload, snapshots, statecharts, guardian

48. **Sandbox ladder** firecracker → gvisor → **bwrap** → **process**: the chat names Firecracker/gVisor/Microsandbox only; `bwrap` (namespaces) and the rlimit `process` tier are our KVM-less fallbacks (ADR-0007 consequence). Firecracker/gVisor are detected but have no launcher.
49. **Live channel transport = files** (tickets / HEAD / acks under `.fabric/live/`), not sockets/gRPC — simplest atomic medium that works headless and in CI; a Studio WS/gRPC transport can sit on the same ticket protocol later.
50. **Live-tunable surface** = numeric leaves of `game_data.json` matched by `content/tune/limits.yaml` + `sim.leash` / `sim.separation`; ranges are ours. Structural edits require `forge build`.
51. **Health probe** = 90-tick forward clone + invariants (finite positions, 0 ≤ HP ≤ max, max > 0, casts resolve). Spec says only "health probe".
52. **ACK target ≤ 500 ms and recovery ≤ 10 s** are our soft targets (spec gives none); tracked in `results/F4.json` `perf`.
53. **Guardian policy**: heartbeat = `status.json` mtime (~2 Hz), hang 5 s default (3 s in acceptance), backoff 0.5 s × 2ⁿ capped 8 s, give up after 5 restarts in 120 s. **Poison-ticket quarantine** (in-flight ticket with no ack is never re-applied) is our addition.
54. **Statechart regions** combat / movement / ai / dialogue / reload and their events (`move/stop`, `freeze/resume/swap`, `intent`, `dialogue_request/reply`, reload 2PC events) are ours; SCXML subset without hierarchy/history.
55. **Session snapshot cadence** 300 ticks + after each commit; snapshots are JSON (not binary) for diffability.

## F5 — Monte Carlo balance, soft-lock detection, save migration, first boss

56. **F5-1 Matchup definition**: a G-BAL-01 "matchup" is a character-select choice = leader ∈ 4 base fighters × starter pet ∈ 3 starters (12 cells, GAME_SPEC §6.1 step 1). The other three base fighters follow without pets. GAME_SPEC does not define "matchup".
57. **F5-2 Target band**: mean win rate must sit in 0.55–0.90 (tuning target 0.72) — a boss that everyone beats (or nobody beats) is "balanced" but useless. Spec gives no band.
58. **F5-3 Dice**: balance seeds vary ±20 % damage rolls, 10 % ×1.5 crits and hostile spawn cells; common random numbers (same seed list for every matchup).
59. **F5-4 Save versions**: v1 (flat prototype) and v2 (layered, int levels) model formats we migrate *from*; v3 is the first shipped layout (profile / roster / world, GAME_SPEC §4.5), canonical JSON + sha256 checksum, atomic tmp→rename with `.bak` fallback.
60. **F5-5 XP**: xp per defeated hostile = tier × 10, granted to every party member (placeholder until progression design, D-005).
61. **F5-6 Rally**: the autoplay leader holds just outside an un-pulled tier-3 boss's aggro ring until every living follower is inside the leash. Before this, whoever was picked as leader tanked the opening alone and the balance runner measured pathing order, not the choice.
62. **F5-7 Boss design**: Cave Warden = tier 3 (×3.2 stats), 3 HP-threshold phases (1.0 / 0.66 summon 2 emberlings / 0.33 enrage ×1.25 atk), telegraphed kit cleave / ember_bolt / quake. Names and numbers are ours (D-005).
63. **F5-8 Choice-level deviation gate**: G-BAL-01 "< 5 % across matchups" is gated on each *choice* (each leader's and each pet's marginal win rate) vs. the mean, measured on ≥ 1000 fights (default 2400). The per-cell (leader × pet) spread is measured and reported as a soft metric (`combo_deviation`) because the combat sim has strong pairwise interactions (a fragile pet following a melee leader); that spread is balance debt, tracked in TODO, not hidden.
64. **F5-9 Tuning space**: Optuna TPE (CPU) over boss HP/ATK and the three starter-pet bonuses; tuned on seed_base 50 000, verified on seed_base 1000 (no overfit to the gate seeds). Fighter stats stay as authored.
65. **F5-10 Runtime soft-lock**: no damage or healing for 1200 ticks (20 s) while both sides live = `softlock`; tick limit = `timeout`. Probe: every ability cooldown at the live-tune maximum must be flagged.
