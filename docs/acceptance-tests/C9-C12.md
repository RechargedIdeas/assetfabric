## Read this first — what "accepted" means here

The task for these four milestones was **real typed interfaces + clearly labelled stubs, with a real CPU path only
where cheap and spec-grounded**. Acceptance therefore verifies:

1. the typed contracts exist (Python + Kotlin where the spec has mobile participating) and round-trip;
2. every capability is listed in `content/companions/c9_c12.yaml` as `real`, `real_unverified_on_device`, `stub` or
   `deferred` (at acceptance 20 · 5 · 8 · 3; **now 25 · 8 · 1 · 3** after the stub-replacement sprint — see the notes
   above), and that
   register agrees with code, locale keys, Android strings, Kotlin symbols and the GroundWeave ladder
   (`forge.registry.check`);
3. every stub **refuses** — Python raises `StubError`, Kotlin throws `StubException`, CLI exits 3, LoomLink answers 501 —
   with a `[STUB <id> <Cn>]` message from a locale key. No stub returns data;
4. the real CPU paths are correct on analytic/known inputs and byte-identical on 2 pinned cores with GPUs hidden;
5. Python and Kotlin agree bit-for-bit on the shared vectors (`tests/fixtures/c9_c12_vectors.json`).

It does **not** show that a phone ran any of this, that depth can be estimated from an image, or that a splat can be trained.
Nothing ran on a device or a GPU. (Since 0.7.4 it *does* show a desktop screen streaming as VP8/VP9 video over signed
HTTP/WebSocket and decoding back above a PSNR floor.)

## Not proven

- **No on-device run.** MediaProjection, MediaCodec H.264, AccessibilityService gestures and Camera2 focus are compiled and
  lint-clean but have never executed on a phone (no device/KVM here) — hence `real_unverified_on_device`.
- No WebRTC/NAT traversal (LoomLink is loopback/LAN HTTP + WS); no desktop hardware H.264 (`mirror-h264-hw@vulkan` stays
  planned: no GPU); no AV1 (C-52); desktop capture is X11 only — Windows/Wayland not wired (C-51).
- Studio is a minimal window (status, mirror viewer, console) + input bridge, not the full SPEC Studio.
- Capture thresholds are unvalidated heuristics; overlap is not measured; ETAs are unmeasured; no reconstruction has been run, so
  the "route" claims are plan-only.
- Nothing has run on a GPU. Since 0.9.2 the ROCm/DirectML ONNX rungs and the OpenSplat runner + cluster job are real code
  (`rocm_ready_unverified` / `real_unverified_on_gpu`, ladder `verified: false`), proven only against a fake onnxruntime,
  the contract-probe trainer and a node that *advertises* rocm; OpenSplat is not bundled (AGPL-3.0, external program) and
  its output is not bit-reproducible (no RNG seed). Other `planned` rungs are declarations.
- DepthAnything V2 / ARCore licences not verified (C-42).
