# Acceptance — F4 Substrate: sandbox, hot reload, snapshots, statecharts

**Fabric delivers:** Substrate sandbox tiers (bwrap namespaces / process rlimits; Firecracker + gVisor detected, documented, no launcher), live channel with atomic hot reload (version ticket → stage/validate → two-phase commit → health probe → rollback), Tier-2 snapshots + WAL, parallel statecharts (GDScript runtime + Python twin with soft-lock analysis), Guardian (crash/hang detect, restart with backoff, resume). (SPEC §6.2–6.3, §13)
**Game proves:** **live tune without a full rebuild** — enemy stats, sim params and a regenerated sprite change inside a running Game Zero. Details: [docs/SUBSTRATE.md](../SUBSTRATE.md).

## Procedure

```bash
pytest -q tests/test_f4_substrate.py
forge accept F4            # phase A (deterministic backlog run) + phase B (live process under the guardian)
forge live serve --headless --allow-fault-injection &   # manual: then forge live set … / forge live sprite …
godot --path games/game-zero -- --scene=live            # windowed; `forge live set …` from another shell
```

## Measured (reference box, 8 vCPU, no GPU, Godot 4.3 headless)

- Ack latency (push → committed) ≈ 80–170 ms (game polls HEAD at ~10 Hz); commit incl. 90-tick probe ≈ 45–52 ms.
- Recovery: crash ≈ 0.8–0.9 s (detect + 0.25 s backoff + boot + resume); hang ≈ 3.9–4.0 s (3 s heartbeat timeout + 0.5 s backoff).
- Session snapshot ≈ 36 KB JSON; scripted snapshot ≈ 23 KB.
