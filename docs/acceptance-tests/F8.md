# Acceptance — F8 Retro / console-style: Console Profile Registry, R1/Q1/V1, ForgeConsole ROM path

**Spec basis.** ASSETFABRIC_SPEC §13 F8 "*optional* · Retro/console-style · Confirm scope first" (scope confirmed by the
Producer, t59u / C-85). Contents come from §6.1 **ForgeConsole** (Console Profile Registry → ConstraintCompiler →
AssetTranscoder → CodeGen → ROMBuilder → EmulatorHarness → CertPack; "three paths unified": real ROMs in emulators,
console-style Godot authenticity profiles/shaders, fantasy consoles), §3 Layer A **ConsoleReadiness**, §3 Layer D
**R1** Retro Render Compiler, **Q1** Pixel Stability Solver, **V1** Retro Validation Harness, §5.1 **C1** (console
constraint solvers / palette / cycle predictors) and **R2** (constraint, fidelity delta, discriminator); GAME_SPEC §4.6
(3 layers + global pixelation / quantisation post-process, nearest filtering), §1/§3 ("8-bit" look, controller-first,
full remapping). Everything the spec does not pin down is `[INFERENCE F8-n]` in [INFERENCES.md §F8](../INFERENCES.md).

**Fabric delivers:** Console Profile Registry (`content/retro/profiles.yaml`, `forge/retro/profiles.py`), C1 palette +
sub-palette + signal-separation solver and AssetTranscoder (`forge/retro/colour.py`, `transcode.py`), R1 LUT generator
(`forge/generators/retro.py`, kind `retro`, 5 gates), ConsoleReadiness (`forge/retro/readiness.py`), own two-pass 6502
assembler with a cycle predictor (`asm6502.py`), ROMBuilder (`rom.py`, iNES NROM-256), EmulatorHarness (`emulator.py`,
cynes headless), V1 + R2 (`validate.py`), `forge retro …` CLI, GroundWeave ops `gen.retro` + `retro.rom`.
**Game proves:** `retro-console` — Settings → *Display style* switches Game Zero live between modern, `gz-native`,
`nes-style` and `gb-style` (+ optional scanlines) with a gamepad, pixel-perfect at an integer scale, colour-blind
palettes still applied, setting saved in the profile; the combat sim is byte-identical in every profile; a real NES ROM
of the field area with the party boots and walks in an emulator.

## Procedure

```bash
source .venv/bin/activate && uv pip install -e ".[dev]"        # dev includes cynes (EmulatorHarness)
forge accept F8                    # full → docs/acceptance-tests/results/F8.json (≈ 40 s on 8 vCPU; Godot 4.3 + Xvfb)
forge retro profiles               # the registry table
forge retro readiness              # ConsoleReadiness per profile
forge retro rom --out dist/retro/game-zero-field.nes [--chr-preview]   # build the ROM (play it in any NES emulator)
forge retro emulate                # boot + d-pad script in cynes
forge retro shimmer                # Q1 shimmer report
godot --path games/game-zero -- --scene=slice --retro=nes-style        # windowed, start in a profile
pytest -q tests/test_f8_retro.py
```

## Measured

Reference box: 8 vCPU, no GPU, Godot 4.3-stable, Xvfb + llvmpipe (Compatibility renderer). `forge accept F8` total
**38.3 s** (generator 1.13 s, ROM + readiness + emulator 5.05 s, Godot headless flows 6.13 s, Xvfb render + V1 + R2 25.99 s).
ROM SHA-256 `2cd18d666f354b1c0aebf5b3b7bb88f1babbda1b38b05836830ab4f37aa20da7` (deterministic). AMD-first: every F8
path is CPU (GroundWeave `gen.retro` / `retro.rom` declare CPU rungs); no GPU rung is needed.

## Not proven here / known gaps

- [ ] The ROM is a **field demo** (party + pet walking the field area), not the game: no combat, farming or menus on NES hardware [F8-6].
- [ ] No GB ROM (gb-style is presentation only); no Genesis/GBA/PS1 profiles; fantasy consoles (PICO-8/TIC-80) and **CertPack** deferred (SPEC §1 hard deferrals).
- [ ] No chip-audio transcode (not in the spec for F8; the game's chiptune stems already play).
- [ ] The HUD is drawn above the pass (readability), so it is not pixel-quantised [F8-10].
- [ ] Real hardware, flash carts and CRT displays untested; only cynes; no human eye test of the look.
- [ ] R2 control is weak: a modern frame scores 0.4836 against the 0.5 capture threshold (reported, not gated) [F8-8].
- [ ] gb-style collapses "crop growing vs ready" to one shade (the ready frame cue carries it) [F8-5].
